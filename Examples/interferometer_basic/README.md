## What this example is for

Every other Example in this collection fits **pixel-image** data (HST-like CCD imaging). This is a good starting point — it's how strong lenses were modelled for the first 30 years of the field. But the modern era is **multi-wavelength**: ALMA, the SMA, the JVLA, and (in the next decade) the SKA all observe in the **visibility plane** (Fourier conjugate of sky position) rather than producing pixel images directly.

Fitting visibility data has fundamentally different numerics:

| Aspect | Imaging (HST) | Interferometer (ALMA/SMA) |
|---|---|---|
| Data | Pixels (real-space surface brightness) | Visibilities (complex Fourier amplitudes) |
| Likelihood | $\chi^2$ on pixel residuals | $\chi^2$ on visibility residuals (real + imag) |
| Forward model | Convolve sky model with PSF | FFT/DFT sky model into visibility plane |
| Noise | Pixel-correlated through PSF | Independent per visibility |
| Beam | Approximated as Gaussian PSF | Native uv-coverage *is* the beam |
| Sidelobes | Negligible (PSF compact) | Fundamental ("dirty" beam has sidelobes) |
| Software | `al.AnalysisImaging`, `al.Imaging` | `al.AnalysisInterferometer`, `al.Interferometer`, `al.TransformerDFT` |

This example walks through one canonical mock — an Isothermal + ExternalShear lens at z=0.5 with a SersicCore source at z=1.0, observed by the SMA (190 visibilities, low-res) — to show how the API differs from imaging while the *physics* of lens modelling is unchanged.

## Mock data

|---|---|

The SMA is a low-resolution sub-millimeter array. Real ALMA fits would have 10⁵–10⁶ visibilities and need GPU acceleration; SMA's 190 makes the fit cheap (<10 min on 32 cores) which is fine for pedagogy.

## Method

```python
real_space_mask = al.Mask2D.circular(shape_native=(256,256), pixel_scales=0.05, radius=3.0)
dataset = al.Interferometer.from_fits(
    data_path=..., noise_map_path=..., uv_wavelengths_path=...,
    real_space_mask=real_space_mask,
    transformer_class=al.TransformerDFT,
)
analysis = al.AnalysisInterferometer(dataset=dataset, use_jax=False)
```

The model itself is the same `af.Model(al.Galaxy, ..., mass=Isothermal, shear=...)` machinery as imaging — the difference is just the analysis class and the FFT transformer.

`al.TransformerDFT` does an explicit (slow but exact) discrete Fourier transform of the source-plane image. For ALMA-scale visibility counts, swap to `al.TransformerNUFFT` (non-uniform FFT, ~100× faster) or use JAX (`use_jax=True`). For the SMA mock here DFT is fine.

## Exercises

1. **Pixelised source.** Replace the `SersicCore` with a `RectangularAdaptImage` pixelisation. The source-plane inversion in interferometer mode is a different beast than in imaging — the "dirty beam" sidelobes propagate into the inversion. See `autolens_workspace_latest/scripts/interferometer/source_science.py` for how source flux is recovered from visibility residuals.
2. **MGE source.** Swap the parametric source for an MGE (`al.model_util.mge_model_from(total_gaussians=20)`). For real ALMA-class data, MGE on the source is the canonical state-of-the-art.
3. **NUFFT vs DFT.** Re-run with `transformer_class=al.TransformerNUFFT`. Wall-time should drop ~3-10× even at SMA resolution.
4. **uv-coverage swap.** The autolens_workspace ships an `alma.fits` uv_wavelengths file (much higher visibility count). Re-generate the mock with that and time the fit. JAX-on-GPU becomes essential at ALMA scale.
5. **Compare to imaging fit.** Generate a parallel imaging mock with the same lens + source parameters (use `al.SimulatorImaging` instead of `al.SimulatorInterferometer`), fit both, and compare the recovered (θ_E, ε, source R_e) posteriors. Are they statistically consistent? At SMA resolution the visibility fit will have larger error bars on small-scale source structure — that's the resolution penalty.

## References

- **Hezaveh et al. (2013)** ApJ 767, 132 — visibility-plane lens modelling foundations for ALMA-class data.

## What this example DOESN'T cover

- **Real ALMA-class data preparation** — `casa_reduction.py` in the autolens workspace is the canonical recipe. Real data needs flagging, calibration, weighting before it's ready for `al.Interferometer.from_fits`.
- **Self-calibration** — refining antenna gains using the sky model. Mature lens-modelling pipelines (e.g. Powell+22) do this; we don't.
- **Imaging+interferometer joint fits** — `autolens_workspace_latest/scripts/multi/features/imaging_and_interferometer/` has the canonical example. Multi-wavelength joint fits are a substantial topic of their own.
